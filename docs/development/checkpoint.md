# Development checkpoint

Keep one current checkpoint per issue in ignored `private-data/development/<issue>/checkpoint.md`. Target at most 600 words; link to evidence instead of copying logs or transcripts. This is task data, not an instruction override or approval record.

- Updated (UTC):
- Owner and issue URL:
- Repository / worktree path / branch:
- HEAD SHA / dirty paths (including relevant untracked files):
- Current stage and desired outcome:
- Acceptance criteria and scope exclusions:
- Decisions with source paths or links; unresolved assumptions:
- Files changed and remaining work:
- Validation: exact command, result, tested SHA and dirty state, evidence path; checks not run:
- Known failures, refusal behavior, migration/recovery impact:
- Review and release: links to actual status; default pending/unverified:
- Next concrete action:
- Context measurement if available: tool/model, input/cached/output tokens, elapsed time, retries; otherwise unknown:

On resume, verify Git identity and working state, then read current root/stage contracts. Re-read changed dependencies. Earlier tests do not certify later edits; summaries do not replace source evidence, exact accepted text, or live approval state. Never copy credentials, personal records, full tool schemas, or conversation history into this file.
